# ADR-0002: 멱등키 기반 Cart 초안에서만 주문 생성

- 상태: 승인됨
- 일자: 2026-09-13

## 맥락

주문 API는 장바구니 초안이 없는 직접 주문 생성을 허용하면 안 된다. 동시에 같은 장바구니에서 주문 전까지 상품과 수량을 충분히 변경할 수 있어야 한다. 주문이 생성된 뒤에는 해당 주문의 내용과 원본 Cart 초안을 바꾸면 안 된다.

별도 `CartLine` 엔티티를 두면 가변 장바구니 라인과 불변 주문 라인의 책임은 분리되지만, 이 MVP에서 Cart는 수정 API가 많은 장바구니 기능이 아니라 주문 전 검증을 위한 짧은 주문 초안이다. 별도 라인 엔티티는 불필요한 모델과 명명을 추가한다.

## 결정

- Cart는 `Idempotency-Key`로 식별한다. `POST /order/cart`의 키는 선택 사항이며, 없으면 서버가 발급한다.
- 동일 키의 `POST /order/cart`는 `ACTIVE` Cart의 `orderLines`를 최신 요청으로 교체한다. 동일 키에서 주문 내용 변경을 허용한다.
- `GET /order/cart`는 같은 키로 Cart를 조회하는 선택 API이며, `POST /order`의 선행 조건이 아니다.
- `POST /order`는 `Idempotency-Key` 헤더를 필수로 받고, 해당 키의 `ACTIVE` Cart가 있을 때만 주문을 생성한다.
- 주문 생성은 Cart의 `orderLinesJson`을 불변 `OrderLine`으로 복사하고, Cart를 `ORDER_CREATED`로 전이한다.
- `ORDER_CREATED` Cart는 더 이상 갱신할 수 없다. 같은 키의 `POST /order` 재호출은 새 주문을 만들지 않고 기존 주문을 반환한다.
- Cart에는 별도 `CartLine` 테이블을 만들지 않고, 비민감 `orderLinesJson` 스냅샷만 저장한다.

## 고려한 대안

### 대안 1: `POST /order`가 주문 라인을 직접 수신

- 장점: Cart 모델이 필요 없다.
- 단점: Cart 생성 없이 주문이 가능하고, 주문 전 변경 가능한 초안과 주문 생성의 선행 조건을 강제할 수 없다.

채택하지 않는다.

### 대안 2: 같은 키에서 요청 본문 변경을 `409 Conflict`로 거절

- 장점: 전통적인 요청 멱등성 해석과 일치한다.
- 단점: 주문 전 장바구니 내용을 변경할 수 없으며, 사용자가 요구한 Cart 동작과 맞지 않는다.

채택하지 않는다.

### 대안 3: Cart와 CartLine을 정규화하고 Cart 라인 수정 API를 제공

- 장점: 복잡한 장바구니 편집, 쿠폰, 재고 예약으로 확장하기 쉽다.
- 단점: 현재 범위에는 과설계이며 `CartLine`과 `OrderLine` 명명을 함께 관리해야 한다.

채택하지 않는다.

## 결과

- 주문 생성은 항상 사전 Cart와 멱등키를 필요로 한다.
- Cart 조회는 편의를 위한 선택 API이며, 조회 이력을 서버가 추적하거나 강제하지 않는다.
- 주문 전에는 같은 키로 Cart 초안을 반복 갱신할 수 있고, 주문 후에는 주문 이력과 Cart 초안이 모두 고정된다.
- 멱등키는 Cart 초안의 식별자이자 주문 생성 재시도 키다. 향후 외부 결제·웹훅의 일반적인 멱등성 정책은 별도 ADR로 분리한다.
